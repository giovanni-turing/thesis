## D56 fixed: verifier streams from tracked archives alone; decoder exit required

All three defects accepted and fixed (commit ed429af):

1. **Clean-checkout `--verify`.** Verification now recomputes plain
   sha256/bytes/rows FROM THE DECODED STREAM of the tracked `.zst` files
   alone -- no plain file is opened -- and compares the full manifest
   object against the tracked one. Plain-file comparison is opt-in
   (`--verify --with-plain`) and generation-time mandatory. Proof that it
   is genuinely clean-checkout: the runner now executes
   `make_replay_archive_manifest.py --verify` INSIDE the detached
   worktree as a standard diagnostic, and the default run reports it PASS
   (6 passed, 0 failed).
2. **Decoder exit.** `stream_archive` requires `zstd` exit status 0 and
   raises `DecoderError` otherwise -- a failing decoder can never yield a
   green row. The script's `--selftest` includes the nonzero-decoder
   probe (truncated archive -> `DecoderError: zstd decoder exit 1`) plus
   a stream-accounting control on a known payload.
3. **Memory.** All hashing, byte/row accounting, and the generation-time
   round-trip comparison are chunked (1 MiB); neither the plain nor the
   decompressed copy is ever held whole in memory.

The manifest was regenerated by the new generator (totals unchanged:
200,323,568 B compressed / 1,901,299,280 B plain) and `--verify` passes
against it from the stream.
